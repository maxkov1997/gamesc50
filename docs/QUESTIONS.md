# Вопросы по GDD

Места, которые GDD не покрывал однозначно. Открытые помечаются в коде `GDD-QUESTION:`.
Пока ответа нет, действует выбранный вариант — самый простой из не противоречащих GDD.

## Открытые

Нет.

## Решённые

| # | Вопрос | Решение | Где в GDD |
|---|---|---|---|
| Q1 | «При розыгрыше» и бонус маны на следующий раунд | Запрещено: операция, дающая ману, в `on_play` — ошибка загрузки | 11.6 |
| Q2 | Ссылки `event_target` / `event_attacker` в триггерах | Доступны в любом триггере и секрете; нет участника — эффект на него пропускается | 9.3 |
| Q3 | Какие триггеры допустимы у чар на поле | Любые | 7.2 |
| Q4 | Позиция призыва у заклинаний и секретов | Новая позиция `center` (⌊n/2⌋); без источника-существа — только `rightmost` и `center` | 11.2 |
| Q5 | Триггеры «этого существа» у чар на поле | Выдаются существам своей стороны по фильтру `watch` (`tag`, `keyword`, `no_keyword`); «это существо» — получившее; счётчики и флаги у каждого свои | 7.2, 11.1 |
| Q6 | Ауры, которые дают ключевые слова, и фильтры аур по ключевым словам | Слои по образцу MTG: слой ключевых слов (зависимости, затем timestamp; петля — по timestamp), потом слой атаки. Очередь триггеров остаётся FIFO (9.1). Петли триггеров ограничивает `MAX_TRIGGERS` из конфига | 7.4 |
| Q7 | Когда разыгранное заклинание уходит в сброс | После полного разрешения эффекта и вызванных им триггеров | 5.3 |
| Q8 | `death_position` у живого источника | Вплотную слева от источника | 8.8 |
| Q9 | Перерождение на полном столе | Существо возвращается и сразу погибает со всеми триггерами смерти | 8.8 |
| Q10 | Какого участника проверяет фильтр условия секрета | Два фильтра: `target` — `event_target`, `attacker` — `event_attacker` | 11.1 |
| Q11 | Когда бот проверяет правило «убрать самое дешёвое» | В начале каждой итерации, до проверки, есть ли действия из таблицы | 12.4 |
